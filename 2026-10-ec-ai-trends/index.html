01 · Protocols

「AIのレジ」は2つの規格で動いている

ACP（Agentic Commerce Protocol）UCP（Universal Commerce Protocol）
主導OpenAI ＋ StripeGoogle ＋ Shopify・Walmart・Target ほか
構成商品フィード／チェックアウト／委任決済の3仕様/.well-known/ucp で店の「できること」を公開し、機能単位で交渉
通信REST（署名・冪等キー付き）REST・MCP・A2A
状態4つ（ready_for_payment ほか）6つ（requires_escalation ほか）
共通売り手はあくまで店（Merchant of Record）。決済も店のPSPで行い、カード番号はAIに渡らない

出典: OpenAI Agentic Commerce（Key concepts / Agentic Checkout Spec）/ ucp.dev Checkout 仕様（2026-08-25版）

01 · ACP — Sequence

ACPで「買って」が注文になるまで

全リクエストに Idempotency-Key・Signature・Timestamp ヘッダー ／ 出典: OpenAI Agentic Checkout Spec / Delegated Payment Spec

01 · ACP — Delegated Payment

カードを「渡さず」に、AIに払わせる

// ③ delegate_payment の allowance
"allowance": {
  "reason": "one_time",
  "max_amount": 2000,
  "currency": "usd",
  "checkout_session_id": "cs_123",
  "merchant_id": "shop_abc",
  "expires_at": "2026-10-09T07:20:50Z"
}
  • この店で（merchant_id）
  • この注文に（checkout_session_id）
  • この金額まで（max_amount）
  • この時刻までに1回だけ（expires_at・one_time）

返金・チャージバック・コンプライアンスは従来どおり店とPSPの責任のまま

出典: OpenAI Delegated Payment Spec（値は例示）

UCPは「AIで無理なら人へ返す」を状態で持つ

「署名された購入意思」（AP2拡張）がない限り、最後は人が確定する前提

02 · Japan

日本の法務・決済：4つの「答えのない問い」

論点いまのルールAIが買うと…
錯誤電子消費者契約法3条：店が確認措置を取らなければ、重過失でも取り消せるAIが確認画面を飛ばしたら、確認措置はあったと言える？
最終確認画面特商法12条の6：分量・価格・支払・引渡・解除・期間を表示。違反は取消権画面を「見る」のがAIなら、表示したことになる？
本人認証EMV 3-Dセキュアを2025年3月末までに原則導入AIはワンタイムパスワードに答えられない
責任の所在経産省の手引き（2026/4）：既存の民法・製造物責任法で整理AIエージェントは「現時点では整理が困難」

公的な答えはまだない。だから設計で備える

出典: 経産省 電子商取引準則・クレジットカード・セキュリティガイドライン・AI民事責任の手引き / 消費者庁 ガイドライン / STORIA法律事務所

03 · Design

法の要請 × 規格の機能 → 実装でやること

日本の論点規格の機能実装でやること
錯誤・確認措置UCPの人による確定・requires_escalation迷ったら continue_url で自社の確認画面へ返す
最終確認画面チェックアウト応答（品目・合計・配送・メッセージ）12条の6の6項目をAPI応答に漏れなく載せる
本人認証（3DS）委任トークン／カード会社のAI向けトークンPSPの対応範囲と、不正時の負担を契約で確認
証跡・責任署名・冪等キー・AP2 mandate誰の指示で何をいくらで、を署名付きで保存

※ 本資料は技術・実務の観点からの整理であり、法的助言ではありません。個別の判断は専門家にご相談ください。
