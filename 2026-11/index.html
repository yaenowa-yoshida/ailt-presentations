01 · How It Works

AIが書いて、人が貼って、AIが確かめる

1 書くClaude Code
2 貼って流す人
3 結果を読むClaude Code
4 判定・検算Claude Code
5 記録シート・Excel
人

ログインと貼り付け

仕様の決定、社外とのやりとり、最後の判断も人（案件2）

Claude Code

書く・読む・判定する

OK・NG・要確認・保留に分け（案件1）、シートやExcelに記録して次の指示を出す

結果の形

文字で残す

案件1は画像を撮らずCSV・JSON・テキストに。案件2は操作ログと金額もJSONに

02 · Stop

想定と違えば、押さずに止まる

違えば発注しない

カートが空か、アカウントと得意先が想定どおりかを先に確かめる

商品と在庫 · 案件1

流すときに選び、戻す

在庫と次回予定を読んで商品を選び、発注した直後に画面からキャンセルする

金額と番号 · 案件2

合わなければ押さない

金額をその場で計算し、注文番号が予想とずれたら確定を押さずに止まる

二重注文の防止 · 案件2

流し終えた注文をブラウザに記録し、同じ注文を二度流さない

案件1では、実行中の表示や画面のスリープ止めも含めた7つを、スクリプトの共通の型にした

05 · Thoughts

なぜ速くなったのかを考えた

2つの案件から考えた、私の見立てです

分ける

流すのは人、判定はAI

結果を文字で受け取るので、AIが判定でき、人もその判定を確かめられる

止まる

見張らずに何度でも流せる

想定と違えば押さずに止まるので、毎回画面を見張らなくて済む

使い回す

速くなるのは2回目からだと思う

一度できたスクリプトを貼り直せば、同じ手順と判定基準で流せる

人に残る

前提と見た目は人が決める

前提が合っているかの確認と、見た目で決めるところは人がする

06 · Other Uses

同じ型が使えそうな仕事

同じ手順を何度も流すか、期待する結果を文字で書けるか。この2つで見分けられると思います

実績に近い

リリースごとの回帰テスト

同じ手順と期待結果を流し直す。直った不具合の確認にも使える

実績に近い

帳票と出力の検算

注文書や工場向けのデータを読み、計算し直して突き合わせる

見立て

移行後のデータ照合

移行先の管理画面を読み、移行元のデータと突き合わせる。読むだけで済む

見立て

受注システムと基幹の突き合わせ

受注番号をキーに両方の画面やCSVを読み、件数と中身を合わせる

向かないのは、本番での取り消せない書き込み、見た目の確認、毎日無人で回したい作業

AIコンサルティング

社内研修

書く人と貼る人に、止まる・残す・照合する決まりと向き不向きを伝える

どれにも共通

ログインと貼り付けは人

AIにパスワードを渡さず、本番では流さない。最後の判断はお客様

夜間の自動実行や大量のケースの検証は、テストツールや検証会社のほうが向いていると思います

Takeaways

持ち帰ってほしいこと

01

書くのはAI、貼るのは人

AIが直接さわれない環境でも、こう分けて自動化できた

02

止まる・残す・照合する

この仕組みがあるので、同じテストを見張らずに何度でも流せる

03

繰り返す仕事から試す

回帰テストや修正の確認のように、同じ手順を何度も流す仕事から始めるとよいと思います
